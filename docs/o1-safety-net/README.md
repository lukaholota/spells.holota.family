# O1 — Сітка безпеки

**Мета:** зробити так, щоб регресію було видно до деплою, а не з треду на Reddit.

На цьому етапі **нічого не рефакторимо**. Жодного «заодно причешу». Ставимо інструменти,
переконуємось, що вони працюють, і йдемо далі.

## Key results

| KR | Про що | Статус |
|---|---|---|
| [KR1.1](kr1.1-schema-baseline.md) | `db/schema.sql` піднімає порожню БД; воркфлоу `db:pull` працює | ✅ |
| [KR1.2](kr1.2-vitest.md) | Vitest встановлено, `bun run test` зелений на реальному тесті | ✅ |
| [KR1.3](kr1.3-test-database.md) | Тестова БД піднімається однією командою, стан скидається між тестами | ✅ |
| [KR1.4](kr1.4-ci.md) | CI ганяє `tsc` + `lint` + `test` і блокує деплой при падінні | ✅ |
| [KR1.5](kr1.5-smoke-before-deploy.md) | Смоук критичних маршрутів навколо деплою, з автовідкатом | 🔄 |

## Порядок

KR1.1 → KR1.2 → KR1.3 → KR1.4 → KR1.5.

KR1.1 перший, бо без відтворюваного `schema.sql` немає тестової БД, а без неї KR1.3 неможливий.

KR1.5 планувався останнім і найдорожчим, із приміткою «можна відкласти». За
[Р9](../DECISIONS.md#р9) він натомість здешевшав: замість Playwright у CI або стейджинг-юніта —
смоук після викочування з автовідкатом, тобто правка наявного воркфлоу плюс один shell-скрипт.
Відкладати стало нічого.

## Чого тут свідомо немає

- **Міграцій.** Див. [Р2](../DECISIONS.md#р2-бд--джерело-істини-міграцій-немає).
- **Другої схеми.** Тестова БД — той самий `schema.sql`, інший інстанс. Див. [Р3](../DECISIONS.md#р3-одна-схема-кілька-баз--це-інстанси-не-дублікати).
- **UI-тестів.** Ніяких, включно з KR1.5: смоук там — це `curl` по трьох публічних маршрутах,
  браузера в O1 немає взагалі. Див. [Р7](../DECISIONS.md#р7-ui-тестів-майже-не-буде-playwright-10-сценаріїв-в-кінці)
  і [Р9](../DECISIONS.md#р9).
