# KR2.5 — Тести на правила PHB 2014

**Ціль:** [O2](README.md) · **Статус:** ☐ не розпочато · **Залежить від:** KR2.2

## Навіщо

Golden-файли фіксують, що система робить. Вони **не знають**, чи це правильно. Цей KR — про
правильність.

Кожен тест тут виведений з тексту правил 2014 і має посилання на джерело. Коли він червоний —
це реальний баг, а не зміна поведінки.

## ⚠️ Редакція

**PHB 2014 + XGtE + TCoE.** Не 2024. Якщо джерело правила неоднозначне або схоже на 2024 —
не гадати, а питати власника. Найчастіші пастки:

| Правило | 2014 (наше) | 2024 (не наше) |
|---|---|---|
| Раса/вид | раса дає ASI | вид не дає ASI, ASI від походження |
| Підклас | рівень залежить від класу (1/2/3) | завжди 3 |
| Риси | тільки замість ASI | ще й origin feat від походження |
| Майстерність зброї | немає | є |
| Походження | навички + інструменти + риса походження (лише деякі) | завжди ASI + риса |

## Готово, коли

- [ ] бонус майстерності за рівнем (PHB 15)
- [ ] модифікатори характеристик, `floor((score - 10) / 2)`
- [ ] HP на 1 рівні й на левелапі (середнє з округленням вгору + CON)
- [ ] таблиця слотів заклинань для повного кастера 1-20 (PHB 113 тощо)
- [ ] мультикласові слоти (PHB 164) — половинні й третинні кастери округлюються **вниз**
      на рівні класу, потім сумуються
- [ ] пактова магія окремо від стандартних слотів (PHB 107)
- [ ] AC: без броні 10+DEX, легка +DEX, середня +min(DEX,2), важка без DEX (PHB 144-145)
- [ ] кількість підготовлених заклинань по класах
- [ ] рівень взяття підкласу по кожному з 12 класів
- [ ] рівні ASI по класах (Fighter і Rogue мають додаткові)
- [ ] кожна розбіжність із golden записана в [KNOWN-BUGS.md](../KNOWN-BUGS.md)

## Формат

```ts
// PHB 2014, с. 164 «Multiclassing → Spell Slots»
it("половинний кастер додає level/2 округлене вниз", () => {
  expect(findCasterLevel([{ class: "PALADIN", level: 5 }])).toBe(2);
});
```

Посилання на сторінку — обов'язкове. Без нього наступна сесія не зможе перевірити, звідки взялось
очікуване значення, і почне «виправляти» правильний тест.

## Що робити зі знайденим багом

**Не виправляти зараз.** Записати в [KNOWN-BUGS.md](../KNOWN-BUGS.md), позначити тест як
`it.fails(...)` або `it.todo(...)` з посиланням на запис, у відповідному golden-файлі поруч зі
значенням поставити `KNOWN-BUG:`.

Виправлення — після O3. Причина: зараз баг сидить усередині функції на 1400 рядків, і виправляти
його там означає ризикнути всім іншим. Після O3 те саме виправлення буде рядком у чистій функції
з тестом навколо.
