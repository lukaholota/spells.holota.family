# KR2.2 — Golden-файли створення персонажа

**Ціль:** [O2](README.md) · **Статус:** ☐ не розпочато · **Залежить від:** KR2.1

## Навіщо

`createCharacter` — 1276 рядків, у яких перемішані валідація, читання з БД, математика правил і
записи. Розібрати це в O3 без сітки неможливо. Golden-файл — і є сітка: він фіксує, що на виході
з тієї самої матриці білдів виходить байт-у-байт той самий персонаж.

## Готово, коли

- [ ] для кожного білда з KR2.1 є `tests/golden/creation/<build-id>.json`
- [ ] тест ганяє `createCharacter` і порівнює **весь** збережений стан персонажа з файлом
- [ ] нестабільні поля (id, `createdAt`, `updatedAt`) нормалізуються, а не ігноруються цілком
- [ ] прогін детермінований: двічі поспіль — однаковий результат
- [ ] `bun run test:golden:update` перегенеровує файли, і це усвідомлена дія, а не побічний ефект

## Що саме знімати

**Не** те, що повернув екшен. Те, що **лягло в БД** — включно зі зв'язками:

- рядок `Pers` цілком
- `PersSkill`, `PersFeature`, `PersSpell`, і решта `Pers*`
- обчислені величини: характеристики після всіх бонусів, HP, AC, бонус майстерності,
  рятівні кидки, слоти заклинань (стандартні й пактові), використання фіч

Читаємо після запису одним запитом із повним `include`, серіалізуємо зі стабільним сортуванням
(інакше порядок рядків з Postgres плаватиме і тести будуть блимати).

## Нормалізація

```ts
function normalizeForGolden(state) {
  // id → послідовні 1..n у порядку сортування, не з БД
  // дати → фіксована мітка
  // масиви → відсортовані за стабільним ключем
}
```

Замінювати id на `null` — погана ідея: тоді тест не побачить, що зв'язок з'єднався не з тим
рядком. Треба саме перенумерація.

## Правила читання диффа

Коли golden червоніє під час O3 — це **не** «тест зламався». Це одне з двох:

1. **Рефакторинг змінив поведінку** → баг у рефакторингу, виправляти код;
2. **Зміна навмисна** (виправили баг із KNOWN-BUGS) → оновити файл **окремим комітом**,
   у повідомленні написати, який саме баг виправлено.

Оновлювати golden-файли «щоб стало зелено», не прочитавши дифф — це знищити весь сенс етапу.
