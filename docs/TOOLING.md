# Інструменти

Код тут і далі писатиме здебільшого ШІ. Отже автоматичні перевірки важливіші за наміри:
все, що не перевіряється машиною, з часом перестає виконуватись.

Список за спаданням віддачі.

## 1. Хук на `PostToolUse` — найбільша віддача

У `.claude/settings.json`: після кожного Edit/Write ганяти `tsc --noEmit` і `vitest related`
на зачепленому файлі.

Зараз петля зворотного зв'язку виглядає так: ШІ пише код → людина відкриває браузер → знаходить
проблему → пише промпт. Хвилини. З хуком ШІ бачить помилку за секунди й виправляє в тому ж кроці,
не витрачаючи увагу людини.

Потребує [KR1.2](o1-safety-net/kr1.2-vitest.md).

## 2. `dependency-cruiser` — межі правилом, а не домовленістю

Заборонити:
- імпорт `@/lib/prisma` поза `src/server/db/`
- імпорт `next/*`, `@auth/*`, `server-only` всередині `src/rules/`
- імпорт серверних екшенів із `src/rules/`

Без цього межі з [O3](o3-rules-engine/) розмиються за місяць — не зі злого наміру, а тому що
наступна сесія не знатиме, що вони є. Правило в CI знає завжди.

## 3. `jscpd` — детектор копіпасти

Прямий контрзасіб проти «один компонент реалізований у 50 місцях, ламається на 51-му». Прогнати
на початку [O4](o4-ui-decomposition/), записати базове число, далі тримати поріг спадним.

Міряти **до**, а не після. Без базової цифри «звели дублікати» — це відчуття, не результат.

## 4. `clean-code-guard` — вже встановлений

Скіл для рев'ю згенерованого коду перед комітом. Ганяти після кожної нетривіальної правки.

## 5. `knip` — мертвий код

Невикористані експорти й файли. Після O3 їх буде багато: `src/domain/pers/` (200 рядків стабів,
`Equipment.ts` порожній), `feats/featChoiceOptionSeed_OLD.ts`.

Не запускати раніше O3 — до того межі коду ще змінюються, і половина знахідок буде хибною.

## 6. codebase-memory MCP

Індекс графа коду. Реально корисний на O3/O4: «хто викликає цю функцію», аналіз впливу перед
перенесенням. На O1/O2 не потрібен — там робота ведеться в кількох відомих файлах.

Індексувати один раз, коли почнеться O3.

## Свідомо не беремо

| Що | Чому ні |
|---|---|
| **Testcontainers** | `scripts/db-clone.sh` і `services: postgres` у CI роблять те саме без залежності від Docker |
| **Prisma Migrate** | БД — джерело істини, див. [Р2](DECISIONS.md#р2-бд--джерело-істини-міграцій-немає) |
| **Kysely** | Потрібна шаруватість, а не інший квері-білдер, див. [Р5](DECISIONS.md#р5-на-kysely-не-мігруємо) |
| **Testing Library / jsdom** | Найгірший ROI на цьому UI, див. [Р7](DECISIONS.md#р7-ui-тестів-майже-не-буде-playwright-10-сценаріїв-в-кінці) |
| **Storybook** | Має сенс після O4, коли компоненти стануть дрібними. Зараз показувати нічого — файли по 2000 рядків у Storybook не заходять |
